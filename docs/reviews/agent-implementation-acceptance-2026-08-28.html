这次改了什么

  1. 统一输入。所有聊天输入，包括单独的视频链接，都进入 /api/chat。Agent 根据意图选择创建、追问、检索或澄清；后端负责权限、额度与幂等。
  2. 按需检索。Agent 自行选择概要、全文关键词检索和片段读取，没有固定的“先检索再回答”顺序。证据有版本化 ID 和时间戳链接，原始转录不进入公开工具消息。
  3. 官方本地接入。锁定的官方 Python Codex SDK／App Server，通过临时 MCP 工具桥接到同一套业务函数。全局 MCP、插件、Shell、Web 等无关能力关闭；不会自动回退到付费 API。
  4. 任务完成后续答。用户原始问题先落库；视频任务、回执、后台等待状态与入队原子提交。视频完成后，worker 调用同一 Agent 的只读阶段，保存回答后再确认队列完成。
  5. 取消与重试。取消后续回答不会取消视频。回答失败可以重试原始输入，不重新扣视频处理额度；过期 worker 不能覆盖新重试。
  6. 消息恢复。Realtime 合并数据库消息；重连和数据库监听就绪后补读一次快照，不轮询。旧快照不能覆盖更新的消息或正在流式生成的回答。

私有问题留在会话中，不混入可复用的公开摘要。模型继续使用配置中的 smart 档，记录运行时、provider、模型、推理档位、用量与耗时；没有按问题长度自动降档。

清理范围与保留边界

删除旧 direct-submit 路由与 hook、固定 RAG 层、重复聊天持久化、旧聊天工具及其失效测试；新契约由 Agent、路由和数据库测试覆盖。没有另存 legacy 代码副本，旧版本可从 Git 恢复。

保留历史聊天消息的读取／渲染兼容，以及现有视频处理 pipeline、用户队列、内部播客供给边界。没有引入第二套数据库、事件总线或通用 workflow 引擎。

收尾时发现并修复的具体问题

  • 云库未发布聊天消息：本次已应用的迁移补入 chat_messages，新版本 /health/ready 增加检查，私有 Agent 表不发布。
  • SUBSCRIBED 可能早于数据库监听就绪：收到官方 postgres_changes / ok 系统事件后再次补读，恢复这个窗口内遗漏的消息。Supabase 官方说明。
  • 提交回执挤掉长问题、首字输出前失败无可恢复消息、旧 worker 失败覆盖用户新重试：均补了回归。
  • 大量短证据片段可能超过消息保存的 part 数上限：限制公开引用条目数量，工具内仍返回完整引用。
  • 首次打开聊天时，线程初始化可能与输入撞车：首屏直接持有稳定会话 ID；过期初始化请求不能覆盖新选择。保留立即输入的浏览器回归，不要求用户等待 URL 变化。
  • 真实登录后的头像服务器／浏览器缓存不一致，触发 hydration 错误：首帧一致，挂载后读取账号缓存；5 项回归及真实重开验证通过。
  • 并行 Next 验收目录未被排除，Tailwind 扫到二进制缓存生成非法 CSS：统一忽略 .next-* 构建目录，未改动全局缓存或 Docker 配置。
  • AI SDK 默认错误日志包含上游请求／响应：使用官方 ToolLoopAgent 流转换接口，在 SDK 日志之前只保留安全状态码；请求失败与流内失败都用真实 SDK mock-model 验证没有泄漏。
  • pg8000 的 SQLSTATE 位于异常字段，而非 psycopg 的属性：补齐 403／409／503 映射，避免把权限或并发冲突报成服务不可用；原始数据库信息不进入公开错误。

剩余关口，不隐去

  1. 确认托管验收部署。主库授权关口已解除；下一步是部署不切正式流量的验收版本。当前生产 Next／API／worker 尚未配置新的签名密钥与续答回调。需确认部署目标，再按 Runbook 对齐服务版本与私有配置。
  2. OpenRouter 行为与质量。在实际服务托管环境跑有上限的创建／否定／检索／续答案例，检查工具行为、源依据、时延和用量。本机地区拒绝不能靠换模型、改代理或付费 provider fallback 掩盖；不做 Codex 与 OpenRouter 的排名对照。
  3. 剩余端到端故障场景。托管回调、在线 INSERT、处理中改目标、取消与重试、有效重复交付仍需在托管验收环境抽查；本机真实闭环与 30 项数据库测试不替代这些检查。
  4. 发布与人工验收。核对部署 revision，CI 镜像／PGMQ 检查通过；真实模型质量和延迟达标后再交人工验收，随后才考虑正式流量切换。已有 UI 改动与 Agent 改动共处工作区，不能未经审阅直接整包部署。

主库迁移已完成，不应重复执行。当前“已实现／本地闭环通过”不等于“线上成熟可发布”。需部署授权才能继续完成托管验收；生产流量仍保留旧版本。

本轮有意没有扩展的能力

只实现一个任务级等待／恢复点，不支持任意步骤 checkpoint、复杂人工审批或多视频并行编排。检索使用全文词法匹配与模型改写查询，尚无语义向量检索。若实测出现召回缺口，或产品需要多次长等待，再按证据重新评估检索与持久化 Agent 框架，不继续扩张自写状态机。

托管验收通过后的人工检查

  1. 输入链接并指定具体目标：只创建一个视频任务；完成后的回答对准该目标。
  2. 输入“只解释链接，不要处理”：不得创建任务或消耗视频额度。
  3. 对已完成视频追问一个精确事实：答案有可追溯依据；源内容没有答案时明确说明。
  4. 视频处理期间改问题、关闭并重开页面：新目标有效，最终回答只出现一次。
  5. 取消后续回答，再检查视频任务：视频仍继续；回答失败后的重试不重新提交视频。
